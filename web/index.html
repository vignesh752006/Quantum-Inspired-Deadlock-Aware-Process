Banker's Algorithm
Classical Safety Baseline

Silberschatz's safety algorithm. Checks whether every process can complete without deadlock. Deterministic, polynomial O(n²m). Our speed baseline.

Deterministic O(n²m) Safety guarantee

QEA Alone
Quantum-Inspired Evolutionary

A population of Q-bit individuals (angle θ representation) searches for low-fitness execution orders. Safety is a soft penalty, not a hard constraint.

⚠️ What We Are NOT Claiming

Intellectual honesty is a first-class project requirement. These points appear in every demo, viva and report review.

💻

QEA is not a quantum computer algorithm

Quantum-Inspired Evolutionary Algorithms use the formalism of qubits — superposition, rotation — as a metaphor for probabilistic search. All computation runs on a classical JVM. No quantum hardware involved.

🚫

No quantum speedup is claimed

Our benchmark shows QEA is 4–120× slower than Banker's Algorithm. This is expected and honest. The QEA's potential value is solution quality on hard multi-objective problems, not raw speed.

🏦

QEA does not replace Banker's Algorithm

Banker's gives a definitive safety verdict in O(n²m). QEA searches for good execution orders. They answer different questions. The hybrid combines both strengths.

🔗

A cycle in the RAG does not prove deadlock with multi-instance resources

Cycle detection is sufficient for single-instance resources only. For multi-instance, a cycle is necessary but not sufficient — Banker's is required for a definitive verdict. Our Step 4 T8 test demonstrates this explicitly.

📏

Results are measured, never assumed

Every number comes from the actual Java benchmark (390 runs). No result is interpolated, averaged-away, or cherry-picked. The fairness panel explicitly shows cases where Banker is faster and QEA brings no improvement.

📚 Concepts

The theoretical foundation behind all three algorithms.

Deadlock & the Four Coffman Conditions

1
Mutual Exclusion
At least one resource held in non-shareable mode.
2
Hold and Wait
A process holding resources waits for more held by others.
3
No Preemption
Resources released voluntarily only.
4
Circular Wait
P₁ waits for P₂, P₂ for P₃, …, Pₙ waits for P₁.

Banker's Data Structures

StructureDescription
Available[m]Currently free instances per resource type.
Maximum[n][m]Maximum demand of each process for each resource type.
Allocation[n][m]Currently allocated instances to each process.
Need[n][m]Remaining need = Maximum − Allocation. Must be ≥ 0.
Work[m]Working copy of Available; updated as processes finish.
Finish[n]Finish[i] = true once process i can complete in simulation.

Which Question Does Each Method Answer?

MethodQuestion Safe State AnswerUnsafe State Answer Complexity
Cycle Detection (DFS) Is there a circular dependency? No cycle → no deadlock (single-instance) Cycle → possible deadlock (multi-instance: check Banker) O(V+E)
Banker's Algorithm Does a safe sequence exist? Safe sequence found → state is safe No safe sequence → state is unsafe (definitive) O(n²m)
QEA Which execution order minimises fitness? Low-fitness safe schedule found Best schedule is still penalised by deadlock weight O(pop × n × m × iter)

Fitness Function

Fitness = 1000 × DeadlockPenalty + 100 × UnfinishedProcesses + WaitingTime + ResourceWaste

Lower is better. DeadlockPenalty = 1 if any process is permanently blocked, 0 otherwise.
In Hybrid mode, unsafe states receive Double.MAX_VALUE / 2 and are never selected as the generation best.

🔬 Experimental Design & Fairness

The rules that ensure results are reproducible and comparable across all three algorithms.

Fairness Principles

  • One SystemState generated per size, per seed — all three algorithms receive deepCopy() of the same state
  • Banker: 5 repetitions (deterministic — repeated only for timing statistics)
  • QEA and Hybrid: 30 repetitions each (stochastic — sequential seeds 1000..1029)
  • All runs logged — no cherry-picking; results.csv contains every single repetition
  • Same hardware and JVM for all measurements
  • Timing via System.nanoTime(), not wall-clock
